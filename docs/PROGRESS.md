## 部署注意

**Ubuntu / NAS 必须带 NetworkManager overlay 启动**，否则容器会另起一个 wpa_supplicant 抢占宿主机
的无线网卡：

```bash
docker compose -f docker-compose.yml -f docker-compose.networkmanager.yml up -d
```

根本原因是基础 compose 未挂载 `/run/dbus` 与 `/run/NetworkManager`，容器内自动探测会退回
`wpa_supplicant` 后端。这一点应在部署文档里写得更醒目，目前只在开发说明里一笔带过。

## 过程中确立的关键决策

- **密码不进数据库**：Wi-Fi 凭据保存在独立的 0600 文件中，API 只回报是否已设置。数据库导出用于
  排障时不含任何密钥。
- **队列即 `media.status`**：不引入第二张队列表，避免两份真相；重启时把 `downloading` 一律退回
  `pending`，磁盘上的 `.part` 由下载器自动续传。
- **相机可达之后才开任务记录**：否则相机不在家时每 30 秒写一条失败任务，一天近三千条噪声。
- **归档迁移只用原子重命名、绝不删除**：同一文件系统内是秒级操作，中断可续；目标已存在同名文件时
  只记录冲突并另存，不覆盖。
- **驱动不共用认证数据**：实测证明 Luna 的握手对 GO Ultra 无效，PRD 7.2 的约束有了实证支撑。
- **不引入 protobuf 依赖**：驱动只需要 varint 与字符串字段，自带的小型线格式编解码即可，镜像不变。
- **休眠相机归类为不可达**：相机睡着时仍会完成 TCP 握手但不应答，报「协议错误」会让用户无从下手，
  改为 `camera_unreachable`。
