## GO Ultra 验收记录

在真实设备上通过 22/22 项检查，覆盖 PRD 11.2 的验收标准：

- 探测到型号与序列号，枚举 51 个媒体文件
- 全部文件都取到精确字节数与拍摄时间，稳定 ID 无重复
- 首次同步落盘字节数与相机一致，归档路径为 `设备/年/月/日/存储/原文件名`
- 重复同步不再下载，已完成文件未被改动
- **断点续传**：保留一半字节的 `.part` 后重新同步，结果的 SHA-256 与完整下载逐字节一致
- 51 个文件的归档路径互不冲突，照片、视频与 LRV 附属文件均纳入同步
- 相机离线时报 `camera_unreachable`，消息可读且标记为可重试

## GO Ultra 协议要点

相机把两件事分在两个端口上，驱动也照此分工。

**清单走 TCP 6666。** 帧格式是 4 字节小端长度前缀（长度含前缀自身）；连接后立即发送
`06 00 00` + ASCII `syNceNdinS` 的同步包，相机原样回显即握手成功；此后每 2 秒发一次
`05 00 00` 心跳，静默约 10 秒相机会断开。命令帧为 `04 00 00` + 12 字节头 + protobuf，
头里含命令码、内容类型 `0x02` 和 3 字节序列号，相机用同一序列号回复。

`GetFileList`（命令 13）的请求字段为 `1=媒体类型, 2=起始位置, 3=数量`，类型 2 表示全部；
响应里重复字段 1 是绝对路径，字段 2 是总数。分页无重叠，可安全遍历大容量相机。

**下载走 HTTP 80，且不需要会话。** `http://<相机IP>/DCIM/Camera01/<文件名>` 直接可取，
支持任意区间的 Range 请求，因此通用下载器与断点续传可以原样复用。注意目录本身
（`/DCIM/Camera01/`）始终返回 403，只有具体文件可读；未识别的路径返回 400 且响应体为 `1000`。

清单不返回文件大小，驱动用并发 HTTP 探测补齐 `Content-Length`。拍摄时间从文件名
`VID_YYYYMMDD_HHMMSS_NNN` 解析。存储 ID 由路径推导，插入存储卡后新目录会成为独立的
存储来源，不会与内置存储的同名文件相互覆盖。

### 安全注意

`GetOptions`（命令 8）的响应字段号与请求的选项 ID 一一对应，而 **选项 36 内含相机 AP 的
明文密码**。驱动只请求 15（序列号）、16（UUID）、30（固件）、48（型号）四项，从不请求 36，
因此密码不会进入进程内存、日志或 API 响应。新增设备信息时务必沿用这一约束。

调试与抓包资料在提交前必须删除 Wi-Fi 密码、访问令牌和序列号。
